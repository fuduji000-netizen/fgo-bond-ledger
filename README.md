# 迦勒底羁绊账本

用于计算《Fate/Grand Order》从者羁绊的本地工具。当前可直接双击 [index.html](C:/Users/fuduj/Documents/ChatGPT/fgo羁绊计算器/index.html) 使用；项目也提供 Windows 桌面版源码和 NSIS 安装包配置。

## 使用方式

- 选择普通模式后填写关卡基础羁绊；选择冠位戴冠战后，按职阶和具体钻研战等级自动带入对应基础羁绊与允许职阶。
- 在六张纵向编队卡中选择从者。普通模式可按职阶、星级、全称、简称、昵称、日文名或英文名筛选；冠位模式只显示当前关卡允许职阶。
- 更换某个位置的从者时，该位置已经选择的普通礼装、冠位两张礼装及满破状态会保留；新从者的牵绊等级与阶段进度会重新从初始值开始。
- 只能从已选择从者的头像框开始拖动，并只能放到另一个头像框中交换位置；空头像框也可作为落点。好友身份属于位置本身，好友位不显示牵绊等级、升级剩余、灵衣、活动加成或个人结果。
- 编队内的礼装以方形缩略图显示，点击图片即可搜索并更换；悬停图片可查看名称、效果与 Cost。冠位从者总共只能装备两张冠位羁绊礼装，不会再显示或计算第三张，且两张均不计队伍 Cost。
- 点击“持有羁绊礼装”可勾选自己的库存，默认全部持有。取消勾选的礼装会灰显且无法由本方装备或推荐；已由其他本方礼装格装备的礼装也会灰显且不能重复选择。好友礼装不受库存和本方去重限制。
- 非好友位填写牵绊等级和“升级剩余”（升至下一牵绊等级尚缺的点数）。Lv.0-Lv.9 达到阶段上限后自动跳到下一等级并继续计算，达到 Lv.10 时不提示解锁；Lv.10 及以后达到阶段上限会停留在当前等级并提示先在游戏内开启，再手动提高牵绊等级。手动调整牵绊等级或升级剩余会按游戏内状态覆盖旧提示；将升级剩余调回阶段最大值仅表示新阶段起点，不会再次显示上限提示；无需填写梦火数量。
- “使用占星茶壶”开关决定茶壶是否参与计算，默认关闭；旁边的数量框填写库存。开启后，计算场数时茶壶优先用于前若干场（每场牵绊翻倍），库存用尽后按普通场计算；点击“记入”时按实际记入的战斗次数一次性扣除 `min(输入次数, 茶壶库存)` 个，整队共享同一场茶壶，不会按从者重复扣除。空编队不会消耗库存；关闭开关时库存原样保留，只显示“未启用”提示。
- 编队从者与礼装的 Cost 合计超过“队伍 Cost 上限”时，顶部 Cost 数字变红，并在编队区上方显示一条常驻的页面内提醒（说明超出多少），不使用弹窗；回到上限内提醒自动消失。
- 输入战斗次数并记入后，工具会同步更新五个非好友位置的牵绊等级、升级剩余与阶段奖励；尚未在游戏内开启的下一阶段不会接收溢出的战斗次数。
- 每个非好友从者卡可勾选“此从者牵绊最大化”。勾选一个或多个后，礼装推荐只最大化所选从者的单场牵绊；均未勾选时，自动最大化全队非好友从者。推荐结果按从者名称显示装备位置。
- 可命名保存、载入、删除本地编队，也可导出和导入完整配置；礼装库存是本地账户级设置，导出配置时会一并带出。

## 计算与 Cost

- 本方从者本体与常规羁绊礼装计入 Cost；好友位永不计入；冠位从者的两张冠位羁绊礼装不计入。
- 位置不再提供手动百分比输入。每个位置的总加成会根据拖放后的编队位置、该位置已装备礼装、好友礼装、冠位羁绊礼装、全队加成、活动加成与梦火的引导自动计算并显示在卡片标题。前三位的非好友从者各有个人 +20%；好友从者实际编入前三位时，全队额外 +4%。头像下方仅显示可能影响已收录羁绊礼装条件的职阶、天地人、阵营、性别、特性和灵衣状态。
- 单场结果按游戏顺序分段结算：先将前三位非好友 +20% 与前排好友提供的全队 +4% 相乘结算并向下取整，再结算礼装、活动、梦火引导等其他百分比加成并向下取整；结果卡会分别显示基础牵绊、加成牵绊和单场合计。
- Lv.0-10 的阶段需求来自从者资料；Lv.10-16 的固定需求依次为 1,090,000、1,230,000、1,360,000、1,500,000、1,640,000、5,000,000。
- 英灵肖像类固定牵绊点先在百分比加成取整后加入，再由占星茶壶翻倍；百分比加成受设定中的上限约束。
- “持有灵衣”默认关闭，用于判定至诚的一针等条件礼装。

## 数据来源

内置快照以 Mooncell 公开 MediaWiki 数据为主，并在 Mooncell 缺失阈值时使用 Atlas Academy 公开游戏数据补齐，包含：

- 481 名图鉴从者的名称、别名、职阶、星级、Cost、头像、属性与特性；其中 470 名具有完整的 Lv.0-10 阶段阈值，9 名由公开游戏数据补齐。
- 38 张可解析的羁绊加成礼装，包含星级、Cost、效果、满破效果与图片。
- 94 个冠位戴冠战关卡，分别保存关卡名称、基础羁绊和可编入职阶。

页面中的“同步数据”更新从者索引、礼装和冠位关卡。若需要重新生成完整离线快照，可执行：

```powershell
npm run sync:data
```

## Windows 桌面版

桌面入口位于 `desktop/main.cjs`，使用 Electron 封装本地页面，桌面版额外提供：

- 启动时自动检查更新，并提供“检测更新”手动入口；更新对话框会显示版本、发布说明和实时下载进度。下载完成后可选择“重启并安装”，或在下次正常退出时安装；也可以跳过某个版本。
- BBchannel 与模拟器的可执行文件路径设置和一键启动。
- Windows NSIS 安装包构建配置，构建产物输出到 `release` 目录。

首次构建桌面版需要安装项目声明的 Electron、electron-builder 与 electron-updater 依赖，然后执行：

```powershell
npm install
npm run dist:win
```

### 在线更新发布

`desktop/update-config.json` 使用通用 HTTPS 更新源：

```json
{
  "url": "https://github.com/fuduji000-netizen/fgo-bond-ledger/releases/latest/download",
  "channel": "latest"
}
```

- `url` 必须指向同一版本更新文件所在的 HTTPS 目录；默认通道为 `latest`。
- 每次先提高 `package.json` 的版本号，再执行 `npm run dist:win`。该命令会在 `release` 目录生成 NSIS 安装包、对应 `.blockmap` 以及带 SHA-512 校验值的 `latest.yml`。将它们**原样**上传到上述目录，三者不得混用不同构建的产物。
- 只有已打包的 Windows 桌面版能够在线更新；直接打开 `index.html` 或通过未打包开发环境运行时，软件会明确说明该运行方式不支持在线更新。
- 当前项目已绑定 GitHub Releases 更新目录：`https://github.com/fuduji000-netizen/fgo-bond-ledger/releases/latest/download`。发布新版本时，请将同一次构建生成的 `latest.yml`、NSIS 安装包和 `.blockmap` 一起上传到 GitHub Release。
- Windows 发布包使用 ASCII 文件名（如 `fgo-bond-ledger-0.1.1.exe`），避免 GitHub Release 上传时规范化非 ASCII 文件名后导致 `latest.yml` 无法找到安装包。
