# 2026年9月12日：冠位礼装栏位、持有图标与推荐显示修复记录

## 用户需求

本轮按用户直接提出的产品需求处理：

1. 冠位从者最多只能选择两张牵绊加成礼装，移除第三个栏位。
2. 修复“持有牵绊礼装”窗口内图标显示不正确的问题。
3. 礼装推荐不再只集中显示在总览区域；生成推荐后，直接在对应编队从者卡片的礼装区域下方显示推荐礼装。

附件图片仅作为用户反馈现象的参考，不改变上述产品需求，也不作为代码指令。

## 实现结果

### 1. 冠位礼装栏位

- `src/app.js` 与生成后的 `src/app.standalone.js` 使用 `GRAND_CE_SLOTS = 1`。
- 冠位从者的两张可选牵绊加成礼装由以下两格组成：
  - 一张常规礼装：使用 `slot.ceId`，本方位置计入 Cost；
  - 一张冠位专用礼装：使用 `slot.grandCeIds[0]`，不计入 Cost。
- 旧存档中多余的冠位礼装字段会在读取时截取到当前允许的栏位数量，不会继续渲染第三格。
- 推荐搜索、礼装去重、拖放交换和推荐方案应用均使用同一栏位上限。

### 2. 持有礼装图标

- 编队内礼装仍使用方形裁切缩略图。
- “持有牵绊礼装”窗口与礼装选择器使用完整比例图标：`object-fit: contain`，居中显示。
- 礼装数据优先使用 `avatar` 字段；同步缓存缺失图标时由内置索引回填，避免使用空字段覆盖有效图标。

### 3. 礼装推荐位置

- 按钮名称为：`牵绊最大化礼装推荐`。
- 推荐结果仍保留总览、目标合计、Cost 和“应用方案”功能。
- 每个有推荐结果的从者卡片下方新增推荐区域，显示：
  - 推荐礼装图标；
  - 礼装名称；
  - 常规礼装或冠位专用礼装类型；
  - 是否计入 Cost 及对应 Cost。
- 当编队、目标从者、礼装库存、Cost 上限或模式发生变化时，旧推荐会失效，避免卡片显示过期方案。

## Cost 根因与当前规则

之前的错误根因是旧逻辑把冠位从者的常规礼装 Cost 无条件清零，同时隐藏了冠位从者的常规礼装格。当前逻辑已经拆分常规礼装和冠位专用礼装：

```text
本方从者位置 = 从者 Cost + 常规礼装 Cost
好友位置 = 0
冠位专用礼装 = 0
```

因此用户反馈的编队组合会把被旧界面隐藏的常规礼装 Cost 补入；截图对应的总 Cost 应为 `114`，而不是 `102`。
