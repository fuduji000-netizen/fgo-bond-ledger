# BBchannel 编队自动配置可行性研究

研究日期：2026-09-10
研究对象：BBchannel 64 位 3.87.20260725（安装于 `E:\BBchannel\BBchannel`）
研究问题：点击账本的“打开 BBchannel”时，账本能否顺带自动完成 BBC 的编队配置。

约束前提：本次研究只做只读检查，没有修改 BBC 的任何文件，也不修改 BBC 程序本体。

## 一、结论摘要

可以做到一部分，但无法做到全部，而且有一个物理上的硬限制。

| 目标内容 | 能否自动写入 BBC | 说明 |
| --- | --- | --- |
| 六个从者位 | 可以 | BBC 配置里有 `servant_0_name` 到 `servant_5_name` 六个字段 |
| 助战位（好友位在第几个） | 可以 | 字段 `assistIdx`，0 起始 |
| 助战从者与助战礼装 | 可以 | 字段 `assistMode`、`assistEquip` |
| 御主礼装 | 可以 | 字段 `master_equip`，值是 `master_info.json` 里的 SN 序号 |
| 我方从者装备的羁绊礼装 | 不可以 | BBC 的编队配置里没有这个字段，我方礼装是游戏内编队界面的事 |
| 技能、宝具、出卡策略 | 可以 | `round1_turn0_skill` 等字段，但账本目前没有这些数据 |

最重要的一条：BBC 的队伍配置只负责“场上是谁”，不负责“我方从者带了什么礼装”。BBC 配置里所有带 equip 的字段都是助战相关（`assistEquip`）或御主礼装（`master_equip`），没有任何一个字段表示我方第 N 位从者装备了哪张礼装。因此“账本自动配好我方羁绊礼装”这件事无法通过写 BBC 配置实现。

## 二、BBC 编队配置的真实存储位置与格式

### 2.1 实时生效的配置

`E:\BBchannel\BBchannel\scripts_settings.json`

结构为 `page0` / `page1` / `page2` 三个页面，分别对应简中服、繁中服、日服。

实测该文件 `page0` 当前内容与本轮提供的 p1 截图逐一对应：

| 字段 | 值 | 截图表现 |
| --- | --- | --- |
| `servant_0_name` | 太公望 | 第 1 位 |
| `servant_1_name` | 巴沙洛缪·罗伯茨 | 第 2 位 |
| `servant_2_name` | 太公望 | 第 3 位，带“助战”角标 |
| `servant_3_name` | 尼莫〔圣诞〕 | 第 4 位 |
| `servant_4_name` | 奥伯龙 | 第 5 位 |
| `servant_5_name` | 克洛伊·冯·爱因兹贝伦(Avenger) | 第 6 位 |
| `assistIdx` | 2 | 与第 3 位的助战标记一致 |
| `assistEquip` | 二维数组 | 三个助战位各自的候选礼装 |
| `assistMode` | 冠位助战 | 与截图中“任意”下拉一致 |
| `server` | CH | 与截图中“简中服 雷电Api 已连接”一致 |

这说明该文件就是界面实时状态的落盘位置，字段命名与界面一一对应。

### 2.2 手动保存的队伍档案

`E:\BBchannel\BBchannel\settings\*.json`

这是菜单“文件”功能保存下来的命名档案，字段结构与上面的单个 page 相同，但没有 `page0` 外层包装。当前存在 `ex1戴冠战.json`、`摩根_光狐_光狐.json` 等四份，说明 BBC 官方支持从外部文件载入整支队伍。

这一点对账本很有利：BBC 自带“读取队伍配置文件”的正规入口，账本只需要生成一份符合格式的档案。

### 2.3 文件占用状态

实测在 BBC 进程运行期间，`scripts_settings.json` 与 `UIsettings.json` 都**没有被独占锁定**，可以用读写方式打开。也就是说账本在技术上具备写入该文件的条件。

### 2.4 助战礼装的可识别范围

BBC 的助战礼装模板位于 `assets\assist\assist_equip`，共 15 张：

> 2024年的、百种光辉、宝石翁、贝拉·丽莎、打神鞭、芙尔摩斯、黑之圣杯、迦勒底午餐时光、迦勒底午茶时光、检查报告、秘密任务、献给幸福的新娘、已成过去的观星之证、至诚的一针、nff

账本当前收录 38 张羁绊加成礼装，与上述模板同名的只有 6 张：献给幸福的新娘、至诚的一针、秘密任务、检查报告、迦勒底午茶时光、迦勒底午餐时光。

其余 32 张（例如各类“英灵逢魔”、英灵肖像系列、迦勒底晚餐时光、名侦探芙尔摩斯等）在 BBC 的模板目录里没有对应文件，说明这些礼装无法被 BBC 的助战识别功能选中。这会影响助战礼装推荐的可选范围。

## 三、账本数据与 BBC 名字表的对齐情况

BBC 的从者名单来自 `servant_info_CH.json`，共 464 条，每条包含主名称、`other_name` 别名数组、职阶、星级。

账本内置快照共 481 名从者，对齐结果：

| 对齐方式 | 数量 |
| --- | --- |
| 用账本 `title` 直接命中 | 431 |
| 用账本 `name` 直接命中 | 6 |
| 用账本 `aliases` 直接命中 | 17 |
| 去掉空格与标点后命中 | 6 |
| 合计可对齐 | 460 |
| 仍无法对齐 | 21 |

可对齐率约 95.6%，直接写入 BBC 配置的可行性较高。

剩余 21 条并非全部是问题，可分三类：

- **BBC 完全未收录（多为不可编入的 Beast 或剧情 NPC）**：马里斯·迦勒底亚斯、E－星玛丽、E－宏玛丽、E－水玛丽、E－火玛丽、BeastⅣ、BeastⅢ／L、BeastⅢ／R、盖提亚、提亚马特、哈桑·萨巴赫。这些本来就不该出现在常规编队里。
- **名称写法不同，需要人工映射**：理查一世（BBC 作“理查Ⅰ世”）、阿尔托莉雅·卡斯特·Caster 版（BBC 作“阿尔托莉雅·Caster”）、亚历山德罗·迪·卡利奥斯特罗（BBC 作“亚历山德罗·卡里奥斯特罗”）、多布雷尼亚·尼基季奇（BBC 作“多布雷尼娅·尼基季奇(Lancer)”）、宇津见绘里濑（BBC 作“宇津见绘里濑(Avenger)”）、“山中老人”（BBC 作“山中老人”，账本带全角引号）。
- **需要消歧义的多形态从者**：岸波白野（BBC 分“女性”“男性”两版）、普勒拉蒂（BBC 分“弗朗索瓦·普勒拉蒂”与“弗兰切斯卡·普勒拉蒂”）。

结论：账本写入 BBC 配置时，需要维护一张人工兜底映射表处理这二十余条差异，不能只靠字符串相等。

## 四、尚未确认的关键问题

以下是技术可行性之外、必须由使用者确认的事项，直接决定实现方式：

1. **BBC 何时读取 `scripts_settings.json`。**本次只读检查能确认该文件未被锁定、且内容与界面一致，但没有验证 BBC 是“启动时只读一次”还是“运行中会重新读取”。如果只在启动时读取，那么“账本先写配置、再启动 BBC”的流程可行；如果 BBC 运行中会把内存里的旧状态回写覆盖，则会冲突。这一条无法在不改动或干扰 BBC 的前提下确定，需要使用者确认或实测。

2. **是否允许账本直接改写 BBC 目录下的文件。**写 `scripts_settings.json` 属于写 BBC 的数据文件，虽然不改程序本体，但会覆盖使用者当前的 BBC 界面状态。更稳妥的替代方案是账本只生成一份队伍档案到 `settings\` 目录，再由使用者在 BBC 里用“文件”菜单手动载入。

3. **我方从者礼装的定位。**由于 BBC 配置结构里不存在该字段，这部分只能提示使用者在游戏内手动装备。如果使用者原本期望的是“连我方礼装一起自动配好”，需要调整预期。

4. **御主礼装与技能策略。**账本目前不采集御主礼装和出卡策略，若要完整还原一支可用的 BBC 队伍，这部分要么留空由使用者补，要么在账本中新增输入项。

## 五、建议的后续做法

按侵入性从低到高排列：

1. **只生成档案，不碰 BBC 目录**：账本导出符合 BBC 格式的 `*.json`，使用者手动放入 `settings\` 或用“文件”菜单打开。零风险，但不算“自动”。
2. **账本写入 `settings\` 目录**：账本在 BBC 的 settings 目录下新建一个以编队名命名的档案，不覆盖任何现有状态。使用者在 BBC 里选一次即可。
3. **账本写入 `scripts_settings.json`**：真正做到“打开 BBC 即自动配好”，但会覆盖使用者当前界面状态，且依赖第一条问题中“BBC 何时读取配置”的结论。

在上述问题得到确认前，不建议直接实施第三种做法。
