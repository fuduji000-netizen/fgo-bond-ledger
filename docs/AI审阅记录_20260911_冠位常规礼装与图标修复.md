# 2026-09-11：冠位常规礼装 Cost 与持有礼装图标修复审阅记录

## 用户反馈与复核结论

用户提供的编队截图显示 Cost 为 `102 / 115`，并确认正确总 Cost 应为 `114`；同时反馈“持有羁绊礼装”窗口的礼装图标不正确。

复核后确认，差额 `12` 不是好友位 Cost，也不是两张冠位专用礼装的 Cost：

- 冠位从者仍有一张**常规礼装**格，该格应当参与编队 Cost。
- 原实现将冠位从者的常规礼装 `ceId` 隐藏，并在 Cost 计算中排除了它。
- 截图中的第一位冠位从者本体 Cost 为 `16`，其已保存但被隐藏的常规礼装 Cost 为 `12`；补计后，编队总计从 `102` 变为 `114`。
- 好友位仍保持不计入 Cost；冠位专用的两张额外羁绊礼装也仍保持不计入 Cost。

## 已修改内容

### 1. Cost 规则与编队显示

- `src/calculator.js`
  - 常规礼装 Cost 不再因从者是冠位而被排除。
  - 冠位专用礼装不会作为常规礼装 Cost 传入计算，因此仍不计入。
- `src/app.js`
  - 冠位从者现在同时显示一张“常规羁绊加成礼装”和两张冠位专用礼装。
  - 编队卡片明确提示“常规礼装计入；两张冠位羁绊礼装不计 Cost”。

### 2. 礼装最大化推荐

- `src/recommendation.js`
  - 冠位从者与好友冠位从者均按三张礼装格处理：一张常规礼装、两张冠位专用礼装。
  - 本方冠位从者的常规礼装受 Cost 上限约束；好友常规礼装不计入 Cost。
  - 两张冠位专用礼装保持不计入 Cost。

### 3. 同步缓存字段回填

- 新增 `src/catalog.js`。
- 同步缓存中同 ID 礼装缺少 Cost、图标、名称等字段时，使用内置快照补全，避免不完整缓存覆盖有效数据。
- 同步数据中的新项目仍会保留，内置快照独有项目也不会因旧缓存丢失。

### 4. 持有羁绊礼装图标

- `styles.css`
  - 编队中的方形缩略图继续使用下半部裁切，以保留原有卡片展示效果。
  - 礼装选择器与“持有羁绊礼装”清单改为居中完整展示，不再继承编队缩略图的下半部裁切规则。
